# Kala Studio — desktop UI

> **UI Note:** Basic AI-generated UI for test. This frontend is a test/preview interface for the chat-first Mechanical Engineering Agent, OpenCascade (`STEP` / `STL`) geometry estimation and handoff, and provider API key configuration.

Chat-first Mechanical Engineering Agent desktop workspace with an integrated, default-active OpenCascade (OCP) Geometry, Estimation & Neutral-File Handoff Workbench (React + TypeScript + Three.js).
This package owns:

- The Vite + React + TypeScript renderer (`src/`).
- The Electron shell (`electron/main.cjs`) that launches the bundled
  Kala Studio backend on a free loopback port and forwards a freshly
  generated, single-shot bearer token to the renderer over a narrow IPC
  channel.
- The `electron-builder` configuration (`electron-builder.json`) that
  produces an NSIS installer on Windows and an AppImage on Linux.
- Local dev/build/packaging scripts (`scripts/`).

The Python backend, packaging worker, and shared API contract live elsewhere
in this repository. Read `../.mece/waves/studio-20261018/WAVE.md` for the
authoritative contract.

## Quick reference

```bash
npm install              # install UI dependencies
npm run typecheck        # TypeScript-only build check
npm run build            # build production UI bundle into dist/
npm run desktop          # dev launcher: builds UI if needed, starts backend, opens Electron shell
npm run desktop:pack     # verify UI + packaged backend present, then run electron-builder
```

## Security posture

- `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`,
  `webSecurity: true`. No Node access in the renderer.
- The renderer talks to the backend at the loopback origin only. The CSP
  shipped in `index.html` and reinforced by the Electron main process blocks
  any remote script, font, or image.
- `window.kalaStudio.getConnection()` is the only exposed IPC; it returns
  `{baseUrl, token}` to the top-level frame on the trusted origin and to no
  one else. We never expose generic IPC channels, never run arbitrary code,
  and never read provider API keys in this package.
- The bearer token is generated by `crypto.randomBytes`, stored in a `0600`
  file under the OS tmp dir for the operator's reference, and never written
  to logs or HTTP responses.
- Browser fallback: if Electron isn't running, the UI prompts for the token
  printed by the launcher. The token lives in session memory only and is
  discarded on reload.

## UI architecture

```
src/
  api/         — fetch-based client, connection bootstrap
  state/       — reducer store + debounced preview controller
  viewer/      — Three.js scene + local primitive mesh & nominal geometry estimator
  components/  — shell, header, sidebar, toolbar, inspector, panels, chat, export
  types/       — strict TypeScript mapping of the WAVE.md contract
  styles/      — single bundled stylesheet (no external fonts, no CDN)
  App.tsx      — wires the preview controller to the store
  main.tsx     — React root
```

Kala Studio is a chat-first Mechanical Engineering Agent:
- **Primary workspace (`ChatPanel`)**: Owns `.app-shell-viewport` by default on boot, showing the live OpenCascade geometry context banner, starter engineering prompts, and provider chat thread.
- **OpenCascade (OCP) Geometry, Estimation & CAD Workbench (`RightRail`)**: Active by default alongside the agent chat with a docked 3D `SceneCanvas` preview, parametric `Inspector` (with closed-form nominal volume, surface area, and bounding-envelope estimates), and `ExportPanel` (`STEP` `ISO-10303-21` and `STL`).
- **View mode switch (`Toolbar`)**: Switches cleanly between `Agent + Workbench` (default) and `3D Canvas Focus` while maintaining a single mounted WebGL `SceneCanvas` instance at all times.
- **Unified workflow**: One shared workflow serves both quick geometry/envelope estimation and neutral-file handoff to external CAD/CAE packages and complete standalone builds using the default OpenCascade engine, without separating or labeling user tiers.

The 3D preview always renders *something honest*. If the backend is slow the
operator sees the local preview computed from the same parametric formula the
server uses; once the server-verified mesh arrives it replaces the local one.
The "Server verified mesh" vs "Local preview — pending server verification"
label in the viewport corner is never both at once.

The chat panel shows exactly the text the backend returned. We do not
synthesise tokens, do not pretend a request is streaming, and refuse to send
to a remote provider unless the operator has ticked the explicit consent box.
Provider credentials are read by the backend environment or saved to the backend's local `0600` settings store via `/api/studio/settings`, and are never echoed back to this UI.

The export & handoff panel produces neutral files (STL, STEP). It does not
launch or attach to native CAD/analysis tools — that distinction is shown
on every integration card.

## Build outputs

`npm run build` writes a production bundle to `dist/` with chunk-split
React and Three.js files. The Electron shell loads `http://127.0.0.1:<port>/`
where `<port>` is the free loopback port the backend bound to; the backend
serves `dist/` from the same origin as the API.

`npm run desktop:pack` is the bridge to `electron-builder`. It checks that
both the freshly built UI (`dist/index.html`) and the packaged backend
binary (`backend/kala-studio[.exe]`) are present, then invokes
`electron-builder` with the project configuration.

## Honest limitations

- This package does not run native CAD or analysis tools. It only produces
  neutral-format files for handoff and surfaces the registry the backend
  reported. If the registry marks an integration as native-only, the UI
  says so and does not pretend otherwise.
- The WebGL viewport is a triangle-mesh renderer, not a B-rep kernel. STEP
  geometry is consumed through the backend's B-rep exporter, but the
  in-app viewport always shows the server's analytic tessellation.
- The desktop build runs unsigned locally. Production distribution requires
  code signing that is out of scope for this cell.
