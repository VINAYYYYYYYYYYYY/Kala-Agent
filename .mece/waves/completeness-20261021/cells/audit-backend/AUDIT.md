## Verified working (no finding)

- **STEP export by design id is real and correctly typed.** `POST /api/studio/export` with the stored design id and `step` returned 200, `content-type: application/step`, `content-disposition: attachment; filename="kala-studio-7955e625daf9.step"`, the real `x-studio-digest`, and a 12,615-byte ISO-10303-21 file whose digest matched the design's `artifacts.step_sha256`.
- **CLI isolation.** The child is started from an argv array with no shell, the prompt is written to stdin only, the environment is the allowlist plus the CLI's own login names, and the working directory is a fresh `tempfile::tempdir` (`cli_runtime.rs:77-92,291-317`). The CLI auth probe reads only exit status, not text (`:562-660`). No credential is forwarded.
- **Consent and model catalog.** Every CLI dispatch branch checks `allow_remote` (`providers/mod.rs:340-375`), and remote or CLI model listings require the same flag (`catalog.rs:389-435`); the listing cache is keyed by a SHA-256 key fingerprint, never the key (`catalog.rs:33-40`).
- **Journal payloads are free of prompt text.** `chat_design.rs:1288-1331` stores `prompt_sha256` and `prompt_chars`, not the prompt; the design events store script digests, measured numbers, warnings and artifact digests, not credentials (`native_geometry/service.rs:560-760`).
- **Cleanup on the timeout path.** With `TMPDIR` set to a fresh directory and `KALA_STUDIO_CLI_TIMEOUT_SECONDS=1`, the 504 timeout left the temp directory empty; the FreeCAD provider's temporary directories from the aborted builds were also gone (`tempfile::TempDir` plus `kala_process` supervision). A backend `SIGKILL` can still leave an OS temp directory, which is inherent without a supervisor.
- **Error envelopes.** The native routes emit the same `{code, message, details}` shape in the ordered (validation) or sorted (route refusal) form; the new design, journal, import and model-catalog refusals map to that shape (`native_geometry/mod.rs:962-1165`, `server.rs:537-563`). No inconsistent envelope was found.
