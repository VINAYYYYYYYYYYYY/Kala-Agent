# Cell corpus-hermetic — REPORT

Scope: make `backend/compat/generate_corpus.py --check` independent of the
length of the temporary directory the generator is given. No product code, no
Cargo workspace, no docs, no packaging, no commit.

## 1. Change

The core `/health` body embeds the generator's run-specific data directory.
The capture already normalised `data_dir` to `<DATA_DIR>` and already took
`body_sha256` over the normalised bytes, but it kept the **raw** `body_length`
and the **raw** `content-length` header. Both grow with the temp path, so a
fixture generated under one `TMPDIR` failed `--check` under another.

| File | Change |
|---|---|
| `backend/compat/corpuslib/http_cases.py` | In `_capture`, for any case with `normalizations`: `body_length` is now `len(normalised_bytes)` (the same bytes `body_sha256` covers) with a `body_length_role`; the raw `content-length` header is removed from the frozen header set and declared in `normalised_headers` (with `normalised_headers_role`) as a self-consistency check. The service-level `normalizations` and `nondeterministic_fields` tables now name the length and the header. |
| `backend/compat/generate_corpus.py` | `determinism.normalized_fields` names the `/health` body length and `content-length`. `_apply_body_contracts` no longer overwrites a normalised length with the character count (a Studio case that ever gains a normalisation would otherwise lose the byte length). |
| `backend/compat/self_check.py` | New invariants: a normalised case must be `body_deterministic: false`; `body_length` must equal the UTF-8 length of its recorded (normalised) `body_text`; `content-length` must not be frozen and must be declared in `normalised_headers`; a header may not be both frozen and normalised; `normalised_headers` may not appear without `normalizations`. |
| `backend/fixtures/corpus/v1/core_http.json` | regenerated by the documented command. |
| `backend/fixtures/corpus/v1/manifest.json` | regenerated by the documented command. |
| `backend/crates/kala-studio/tests/corpus_fixture.rs` | `CORPUS_SHA256` moved to the new digest. |
| `backend/compat/README.md`, `backend/fixtures/README.md` | digest tables/text, the normalisation rule, and the current case/route counts. |

Regeneration command (documented, repository venv):

```bash
.venv/bin/python backend/compat/generate_corpus.py
```

Of the twelve checked-in fixture files, **ten are byte-identical** after the
regeneration, including `studio_http.json`; only `core_http.json` and
`manifest.json` moved. The product source pin did **not** move (identical
`source_state.python_sources`; the manifest diff is the digest, the file-hash
entry and the normalisation wording, plus the always-excluded git worktree
list). There is no product change in this cell.

`core.health` now records `body_length: 374` — the byte length of the
normalised document — instead of `415`, and its `headers` no longer freeze
`content-length: "415"`.

## 2. Why the old fixture failed

Let `L` be the length of the temp data directory. The raw body is
`374 + L − 10` bytes (`<DATA_DIR>` is 10 bytes):

| Data directory length | Raw `/health` bytes | Normalised bytes |
|---|---|---|
| 44 (`/tmp/kala-corpus-gen-XXXXXXXX/http/core-data`) | 408 | 374 |
| 51 (the committed fixture's generating run) | 415 | 374 |
| 122 | 486 | 374 |

The first two rows explain Opus's finding exactly (committed 415, clean
`TMPDIR=/tmp` 408), and the 44-char data directory is what a default `/tmp`
run produces. Measured live with the real app (`create_app` + `TestClient`,
two data directories): 44 chars → status 200, raw 408, `content-length: 408`,
normalised 374; 122 chars → raw 486, `content-length: 486`, normalised 374.

## 4. Two-TMPDIR proof

Both runs use the checked-in corpus and a fresh temp `HOME` /
`KALA_AGENT_DATA_DIR`; only `TMPDIR` and the (irrelevant) caller data dir
length differ.

| Run | `TMPDIR` | generator data-dir length | caller `KALA_AGENT_DATA_DIR` | `--check` |
|---|---|---|---|---|
| A | `/tmp` | 44 | 34 chars | exit 0, `determinism check passed` |
| B | `/tmp/kala-tmpdir-proof-abcdefghijklmnopqrstuvwxyz-0123456789/nested/one/more/level` (82 chars) | 126 | 137 chars | exit 0, `determinism check passed` |

```bash
TMPDIR=/tmp .venv/bin/python backend/compat/generate_corpus.py --check
TMPDIR="$LONG" .venv/bin/python backend/compat/generate_corpus.py --check
```

Before the fix, the raw lengths of these two runs differ by 78 bytes
(408 vs 486), so the second comparison cannot pass with a frozen length.
`self_check.py` was also run with `TMPDIR="$LONG"`: exit 0, `self-check OK`.
The caller's `KALA_AGENT_DATA_DIR` length has no effect (34 vs 137 chars,
both green), matching Opus's two-length observation.
