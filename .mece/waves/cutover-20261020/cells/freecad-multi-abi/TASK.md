# freecad-multi-abi: make the bundled FreeCAD adapter work with any supported FreeCAD Python
Read `../packaging/REPORT.md` (Round 2: the vendored set is coupled to the build host's FreeCAD Python cp314, while the official FreeCAD 1.1.4 AppImage is py311) and `backend/crates/kala-cad-providers` (how the FreeCAD provider builds sys.path and launches FreeCADCmd).
Own: the vendoring/staging parts of `studio/scripts/native-backend.cjs` (and its tests), `packaging/linux/**`, `packaging/windows/**`, `adapters/freecad/vendor.json`, and the FreeCAD sys.path selection in `backend/crates/kala-cad-providers` (minimal; keep its tests and differential green).
1. Vendor the adapter's runtime dependencies for EVERY CPython ABI that current FreeCAD releases ship: cp311, cp312, cp313, cp314 (Linux manylinux x86_64; and the same set of win_amd64 wheels in build-windows.ps1), into per-ABI dirs, e.g. `site-packages-cp311/`. Pure-Python packages may be shared. Record all digests in `vendor.json`.
2. At runtime the provider detects FreeCADCmd's Python version (a cheap probe, cached) and puts ONLY the matching ABI dir on sys.path. An unsupported ABI gives an honest provider-unavailable reason naming the version, never a crash.
3. Prove it: on this host (cp314), the extracted AppImage FreeCAD L-bracket = 35571.416047 still passes. Run a unit/integration test of the selection logic for cp311–cp314, and check every ABI dir imports cleanly via a matching interpreter if one is available (`uv python` or mise may provide 3.11–3.13 without sudo; if not, record "not run"). Rebuild the AppImage and record its path, size, and sha256.
USER DATA rule in every shell. No sudo, commit, push, or credential reads. Gates: npm typecheck/test/build, the kala-cad-providers Rust gates. REPORT.md.
