# api-errors-fix: the latent HTTP_500_BAD_REQUEST bug (found by api-core-r1, confirmed by Opus)
`src/kala_agent/api/errors.py` line ~146 compares against `status.HTTP_500_BAD_REQUEST`, which Starlette does not define (verified: `'HTTP_500_BAD_REQUEST' in dir(starlette.status)` is False). Every HTTPException with a 4xx status other than 404/405/413 therefore raises AttributeError inside the handler, and the client gets a generic 500 `internal_error` instead of the intended `request_rejected` with the real status. The bug has been present since commit 1bc2ecf.
