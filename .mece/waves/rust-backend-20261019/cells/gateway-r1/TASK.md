# gateway-r1: kala-runtime (model gateway)
Follow `../CONVENTIONS.md`. Port `src/kala_agent/runtime/model_gateway.py` completely (plus the runtime `__init__` exports it contributes) into NEW standalone `backend/crates/kala-runtime`, module `gateway`, over the accepted kala-kernel (policy), kala-budget, kala-contracts, kala-json, and kala-tools (protocol). All are read-only path dependencies. This is the LLM connection layer: provider request shaping, egress policy and allow-remote consent through the PolicyEngine, budget reservation and settlement, retries and timeouts, response validation, artifact classification, and side-effect levels. Never log or echo credentials. Use the same HTTP client stack as the accepted kala-studio. Read ADR-0001 (local-first, no egress by default) and ADR-0003, and every gateway test in tests/unit, tests/security, and tests/integration. Differential: drive the Python gateway and the Rust gateway against the same in-process mock provider servers (success, malformed, oversize, slow, 4xx/5xx, redirects) with the same policy and budget states, and compare decisions, budget ledger bytes, requests sent (headers minus secrets), and results. Zero unexplained mismatches. Full Rust gates. A later cell (agent-r1) will build the agent runtime on top of this crate.
