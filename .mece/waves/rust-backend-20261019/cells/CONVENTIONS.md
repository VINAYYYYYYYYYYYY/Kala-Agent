# Rust cell conventions (Opus conductor, 2026-10-19). Every Rust worker follows these.

- **Scope:** the user wants ALL of Kala's own backend code in Rust. CAD engines are never re-implemented: OpenCascade stays C++ (phase 1: the Python/OCP geometry worker; phase 2: a narrow C++ adapter called from Rust), and Solid Edge is reached via the bridge.
- **Crate layout:** a NEW standalone crate under `backend/crates/<name>/` with its own `[workspace]` and local `Cargo.lock`. Consume accepted crates (kala-json, kala-contracts, kala-persistence, kala-repositories, kala-budget, kala-artifacts, kala-process, kala-domains, plus kala-kernel once accepted) READ-ONLY via path dependencies. Never edit another crate, root manifests or lock, Python source/tests, shared fixtures, adapters, or studio/**. If an accepted crate lacks an API you need, report exact evidence; do not patch it.
- **Fidelity:** port the ENTIRE named Python module(s): every public function, validation code and message, error precedence, canonical JSON/digest bytes, aware-timestamp semantics, Decimal precision, and limits. Use the accepted kala-json for lossless JSON and canonical hashing. No recursion that can overflow on attacker-sized input.
- **Tests:** (1) a live differential against the repo Python (test-only: `/home/v9i/Projects/Kala-Agent/.venv/bin/python -I` with `PYTHONPATH=src`), covering a meaningful and randomized deterministic corpus of the module's public behaviour, with zero unexplained mismatches; (2) security and edge cases from the matching Python tests (`tests/unit`, `tests/security`, `tests/integration`); (3) `cargo fmt --check`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo test --locked` in debug and release, `cargo build --release`; (4) `cargo check --target x86_64-pc-windows-gnu` if the target is installed (say so if not).
- **Honesty:** no runtime-cutover, Windows-runtime, speed or readiness claims. List every intentional difference.
- **Coordination:** no commit, push, deploy, delegation, or credential reads. Other workers run concurrently on other paths.
- **REPORT.md** in your cell folder: public API, changed paths, exact test counts and differential results, compatibility and security evidence, and remaining gaps.
- **USER DATA IS OFF LIMITS (added after the cli-r1 incident, 2026-10-20).** `/home/v9i/.local/share/kala-agent/**` is the user's real data. Before running ANY binary or Python entry point, every shell session MUST first run `export RUSTUP_HOME=/home/v9i/.rustup CARGO_HOME=/home/v9i/.cargo; export HOME=$(mktemp -d) KALA_AGENT_DATA_DIR=$(mktemp -d) KALA_STUDIO_DATA_DIR=$(mktemp -d) XDG_DATA_HOME=$(mktemp -d)`, and pass explicit temp `--data-dir` values.
